# 赛事成本基准的场次组合与盈亏分析

`running_hours` 是各赛段实际制作时数；同场日多段的联合档位持续时间需按 `start` 和 `end` 看可重叠时段。`scope` 是费用适用场地组，`unit` 值 `day`、`running_hour`、`concurrent` 分别按场次日、实际制作时长、同时运行峰值触发。门槛为大于等于，阶梯项可同时适用；`day`、`concurrent` 和 `discount` 每个适用场地日计一次，`running_hour` 的正费用按达到门槛后的适用小时计（含达到门槛的第一个小时），`once` 同一共用准备只收一次。同场地同一制作设备可顺序复用，重叠时仍需另外一套。实付回执对 `term` 的确认金额进行冲抵，部分已付和已确认未付都影响后续可用经费。`moved` 表示按已选方案移动相应赛段，退出与移动不自动取消已经签认的共用采购；未选方案时保持原排期并指出待定。场日收支使用同一元口径，收入上、下界不补作已经到账。

## 数据包

`sample/` 是本地合成的业务记录，均为 UTF-8 CSV；`table-format.json` 给出各表的列顺序与标量类型，`str` 中 `-` 表示不适用，逗号分隔多值。不同表中同名业务标识用于关联，具体含义见上文。资料入口只检查表头和格式，不对业务状态作判断。

## 运行

使用 Python 3.11 标准库，不需要安装三方依赖。读取样例与运行资料检查：

```sh
python3 intake.py
python3 -m unittest discover -s tests -v
```

也可以将同格式的资料目录作为 `intake.py` 的位置参数。
